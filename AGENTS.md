# AGENTS.md

1. Код должен быть правильным, професиональным, простым, читаемым, типизированным, единообразным и идиоматичным. Избегай лишней сложности и абстракций, перегруженых функций.

2. Перед созданием нового кода изучи проект. Если похожая реализация есть - переиспользуй её. Не создавай дубликаты.

3. Строго соблюдай Feature-Sliced Design. Не смешивай слои и их ответственность. Выстраивай удобную и понятную иеерархию/архитектуру.

4. Переиспользуй строго существующие компоненты(из проекта, из shadcn), логику, хуки, утилиты и паттерны проекта если таковые имеются. Используй принцип: сначала изучи → переиспользуй → упрости → только потом создавай новое.

5. UI и UX должны быть красивым, удобным, понятным, не перегруженым, единообразными во всём приложении. Используй палитру строго по теме.

6. Бизнес-логику отделяй от UI. Каждый модуль должен отвечать только за свою ответственность.

7. Не дублируй состояние, логику и данные без необходимости.

8. Не изменяй unrelated-код и не делай лишний рефакторинг.

9. Используй supabase и все его функции как backend.

10. Перед завершением проверь типы, ошибки(npm run prepare) и соответствие существующим паттернам проекта.

11. Сейчас при открытии приложения в браузер сразу грузятся все записи всех сущностей. Это плохо и не масштабируется. Задача — постепенно, итерациями, перенести всю работу с записями на сервер (в базу данных), чтобы в браузер попадало только то, что реально нужно открытой странице.

    Первая итерация уже сделана: всю работу с записями, где это было возможно, вынесли в асинхронные утилиты (`record-queries` и соседние). Сейчас внутри они читают локальные данные, но позже их содержимое можно будет заменить на обращение к базе, не трогая вызывающий код. Дополнительно: записи начали подгружаться под конкретную страницу по мере надобности, а изменение записи теперь сначала сохраняется в базу и только потом в локальную копию.

    Нюансы: часть мест так переделать пока не вышло — остались чтения «всех записей сразу» и несколько временных обходов, а расчёт формул пока живёт в браузере. Это известный долг, закрываем его следующими итерациями.

    Как теперь писать код:
    - Не считай, что в памяти лежат все записи сущности — там только то, что успели загрузить под текущую страницу. Не добавляй новых мест, которые читают все записи всех сущностей разом.
    - Читай записи через асинхронные утилиты (`getEntityRecords`, `getEntityRecordById` и другие из `record-queries`), а не напрямую из `entity.records`.
    - В отрисовке бери записи из контекста значений (`ctx.getRecords` / `ctx.getRecord`) — он синхронный и сам ничего не грузит.
    - Делаешь новую страницу — объяви, какие сущности ей нужны (`usePageRecordScope`). Для списков, где записи из разных сущностей, подгружай их по идентификаторам (`useEnsureRecordsByIds`).
    - Любое изменение записи — сначала сохрани в базу, потом обнови локальную копию. Без правок «наугад» с последующим откатом.
    - Не плоди временные обходы вида «подождём немного и синхронизируем» — это долг, а не образец для подражания.

Главное правило: **професионально, чисто, красиво, удобно, просто, единообразно, предсказуемо, без дублирования**
